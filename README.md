# PMI Studio

Upload a STEP AP242 file and get, in one place:

1. **PMI / GD&T** — the dimensions, geometric tolerances and datums in the file, shown on the 3D model as numbered
   balloons and datum flags. Add or edit a characteristic by picking geometry in the view; it is written back
   into the STEP file.
2. **A 2D drawing** — front, top, right and isometric views by exact hidden-line removal on the B-rep, a balloon
   for every characteristic, datum flags, overall sizes and a table of the PMI. Download it as SVG or DXF.
3. **Features** — holes, pockets, slots, steps, bosses, chamfers, blends and the rest, recognized from the
   geometry alone, each with its size, confidence and the evidence behind it.

```
backend/   FastAPI + OpenCASCADE (cadquery-ocp)
frontend/  React 19 + TypeScript + Vite + Tailwind v4 + three.js
```

## Run

```bash
./dev.sh              # backend :8001 + frontend :5174; first run creates the venv, installs npm deps, generates the samples
```

or by hand:

```bash
cd backend && python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
.venv/bin/python scripts/make_samples.py          # the STEP samples (not in git)
.venv/bin/uvicorn app.main:app --reload --port 8001
cd frontend && npm install && npm run dev          # proxies /api to :8001
```

Open http://localhost:5174, then **Samples** (or **Open** your own `.step`).

Tests: `cd backend && .venv/bin/python -m pytest tests`. Frontend: `cd frontend && npm run build` (typecheck and bundle).

## STEP files are not in this repository

The samples and test corpora are **generated by the scripts in `backend/scripts/`** (`make_samples.py` runs them
all) and were tested with those generated files. Nothing downloaded or uploaded is committed: `*.step`, `*.stp`
and `*.p21` are git-ignored. The accuracy benchmark uses third-party datasets that you download yourself (below).

## The three workspaces

**GD&T.** The PMI manager lists the datums and characteristics, and *Add GD&T* authors a new one. A characteristic
read from the file's semantic (XCAF) PMI can be edited in place; one recovered from the STEP text cannot, and says so.

**Features.** Every recognized feature with its size, confidence and evidence, and any other reading that fits.
Clicking a row or a face shows the feature in the view. Curved faces no recognizer can explain are listed as unexplained.

**Drawing.** The sheet drawn from the part, with balloon numbers matching the 3D view and the PMI table. Overall
sizes are measured from the geometry and drawn grey: they are not PMI.

## How accurate is the feature recognition?

Scored per face against MFCAD++ (59,655 third-party parts, CC BY), developing on `val` and reporting on `test`:
**95.5 %** of faces get the right kind of feature and **88.6 %** the exact class (8,949 test parts, 268,982 faces).
Those parts are synthetic and prismatic; real parts still need review. Method and weak classes:
`backend/benchmark/mfcadpp/`. To reproduce, download the dataset in a browser (the server refuses scripts) and unzip it
into `backend/benchmark/data/mfcadpp/`, then `scripts/mfcadpp_benchmark.py --split test`.

Curved faces no recognizer can explain become `unknown` features; they are reported, not guessed. Ambiguous calls
carry their alternative readings (`alternatives`, `ambiguous`).

## How PMI is read and written

* Two readers are merged: the XCAF reader (`pmi_xcaf.py`, geometry-linked, editable) and a Part-21 text reader
  (`pmi_part21.py`) that fills in what XCAF drops and is the only source when the PMI is not linked to geometry.
* A characteristic keeps the drawing's units (mm, in, deg); geometry is always mm. A PMI write on a drawing that is not
  in mm is refused, because OpenCASCADE's writer would rewrite every inch value as mm.
* A write rewrites the whole file, so the app compares every characteristic it was not asked to change and **refuses
  the write if any changed or vanished**. Authoring is reliable on files this app wrote, not yet on files from other
  CAD systems.
* A drawing's balloon numbers: naming a characteristic with its original balloon number (`"5"`, `"C5 - bore dia"`) makes
  the app use it as the id.

## API

| Method | Path | |
|---|---|---|
| POST | `/api/models` | upload a STEP file |
| POST | `/api/models/blank` | a blank block to author PMI onto |
| GET / POST | `/api/models/samples`, `/samples/{name}` | the generated samples |
| GET | `/api/models/{id}` | summary: PMI, datums, features, warnings |
| GET | `/api/models/{id}/mesh.bin` | the mesh, packed little-endian |
| GET | `/api/models/{id}/features` | recognized features with evidence |
| GET | `/api/models/{id}/drawing`, `.svg`, `.dxf` | the 2D sheet as data, SVG or DXF |
| POST / PUT | `/api/models/{id}/pmi`, `/pmi/{cid}` | add or edit a characteristic (returns a new model id) |
| GET | `/api/models/{id}/file` | the STEP file as written |
